Архитектура OrbitWatch

Полная карта серверной части — три микросервиса, общая библиотека контрактов, межсервисные вызовы и схема БД. По этой карте пишется весь backend.

стек: Kotlin + Spring Boot 4 архитектура: hexagonal · microservices БД: PostgreSQL + Liquibase связь: REST + события источник: CelesTrak

00 · Decisions

Что зафиксировано

  • Полный сервер — три сервиса: catalog-service, satellite-service, user-service. Каждый — свой репозиторий, свой порт, своя схема БД.
  • Общий контракт — библиотека shared (com.artemwhite:shared): общие enum'ы, ссылки на объекты, события и структура ошибок. Сервисы зависят от неё на этапе компиляции.
  • Связь между сервисами — синхронно через REST, асинхронно через события (порт скрывает транспорт).
  • Каждый сервис — внутренне гексагональный: domain (чистый Kotlin) + application (use cases) + web/persistence/outbound (адаптеры).
  • Пагинация — единый тип PageResult<T> в домене каждого сервиса; контроллеры принимают page/size и зажимают size ∈ [1, 100].
Границы ответственности — catalog отвечает «что это за объект» (реестр, категории, статус). satellite — «где он сейчас» (TLE, орбиты, пролёты, события схода). user — «кто и что сохранил» (пользователи, избранное/коллекции, уведомления, пресеты).

04 · Shared Library

Библиотека shared

Всё, что нужно нескольким сервисам одновременно. Это и есть «контракт взаимодействия»: поменял тип здесь → поднял версию → у потребителей ошибка компиляции.

05 · catalog-service

catalog-service — реестр объектов

Источник истины о том, что за объект: имя, категория, описание, источник. Каталог фильтруется через JPA Specification и отдаёт результат постранично.

Домен + приложение

Адаптеры

Паттерны — Factory Method: SpaceObject.create(...). Specification: SpaceObjectSpecifications.from(filter). Repository: порт SpaceObjectRepository + JPA-адаптер.

06 · satellite-service

satellite-service — орбиты и положение

Отвечает где объект: TLE из CelesTrak, расчёт положения, предсказание пролётов, события схода с орбиты.

Домен + приложение

Адаптеры

Паттерны — Builder: PassQuery.Builder. Factory Method: Satellite.create(...). Proxy / ACL: CatalogRestClient → порт ObjectRegistryClient.

07 · user-service

user-service — пользователи и избранное

Отвечает кто и что сохранил: учётные записи, избранное/коллекции, уведомления, пресеты визуализации. Принимает события от satellite-service и рассылает уведомления через Visitor.

Домен: модели, события (Visitor), порты

Приложение: use cases

Адаптеры: web + outbound

Паттерны — Visitor: SatelliteDomainEvent.accept() + SatelliteEventVisitor<R> (реализации NotificationTextBuilder, NotificationSeverityAssessor). Strategy: PasswordHasher→BCrypt, NotificationSender→Logging, TokenProvider→Opaque. Proxy / ACL: CatalogRestClient. Factory Method: User.create(), Favorite.create(), Notification.create(), Collection.create(), VisualizationPreset.create().

08 · Flows

Ключевые потоки

Положение спутника (client → satellite, проверка в catalog)

Синхронизация → сход с орбиты → уведомление (все три)

Приём события → уведомление (Visitor в user-service)

Избранное (client → user, резолв в catalog)

09 · Data Model

11 · Deploy

Конфигурация и запуск

Секреты — только через env. Каждый сервис — собственный docker-compose.yml со своим postgres и своей базой данных.

# server/catalog-service/docker-compose.yml (реальный файл из репозитория)
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: catalog
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
    ports: ["5432:5432"]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d catalog"]
      interval: 5s
      timeout: 3s
      retries: 10

  catalog-service:
    build:
      context: .
      args:
        GITHUB_ACTOR: ${GITHUB_ACTOR:-}
        GITHUB_TOKEN: ${GITHUB_TOKEN:-}
    environment:
      DB_URL: jdbc:postgresql://postgres:5432/catalog
      DB_USERNAME: postgres
      DB_PASSWORD: postgres
      SERVER_PORT: "8080"
    ports: ["8080:8080"]
    depends_on:
      postgres:
        condition: service_healthy

env-переменные (из application.yml)

СервисПеременные (значение по умолчанию)
catalog-serviceDB_URL, DB_USERNAME, DB_PASSWORD, SERVER_PORT=8080
satellite-serviceDB_URL, DB_USERNAME, DB_PASSWORD, SERVER_PORT=8082, CATALOG_BASE_URL=http://localhost:8080, CELESTRAK_URL, EVENT_URL=http://localhost:8083/api/v1/events
user-serviceDB_URL, DB_USERNAME, DB_PASSWORD, SERVER_PORT=8083, CATALOG_BASE_URL=http://localhost:8080
Единый запуск — корневой docker-compose.yml поднимает все три сервиса с одним postgres и тремя базами (catalog, satellite, user — две последние создаются init-скриптом). Запуск: GITHUB_ACTOR=… GITHUB_TOKEN=… docker compose up --build.
Статус деплоя — Dockerfile и docker-compose.yml есть у всех трёх сервисов; каждый поднимает свой postgres и свою базу (catalog, satellite, user).
Порядок реализации — сначала shared (типы), затем catalog-service целиком (домен → Liquibase → JPA → use cases → REST → тесты), затем satellite-service (TLE + расчёт + вызовы в catalog), последним user-service (auth + избранное + приём событий).
